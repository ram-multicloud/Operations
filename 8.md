# Azure VM Monitoring with Azure Monitor

A step-by-step hands-on lab for students. You will create a virtual machine on Azure, enable monitoring, send logs from the VM, and view those logs in Log Analytics.

---

## What You Will Build

```
Virtual Machine  →  Azure Monitor Agent  →  Data Collection Rule  →  Log Analytics Workspace
```

By the end of this lab you will be able to:

- Create a Linux VM using Azure CLI
- Set up a Log Analytics Workspace
- Install the Azure Monitor Agent on a VM
- Create a Data Collection Rule to collect Syslog
- Generate dummy logs from inside the VM
- Query and visualize logs using KQL in Log Analytics

---

## Key Concepts

| Term | What it means |
|---|---|
| **Log Analytics Workspace (LAW)** | A storage and query engine in Azure where all your logs are kept |
| **Azure Monitor Agent (AMA)** | A lightweight agent installed on your VM that ships logs to Azure |
| **Data Collection Rule (DCR)** | A rule that tells AMA what to collect (e.g. Syslog) and where to send it |
| **DCR Association** | The link between a DCR and a specific VM |
| **KQL** | Kusto Query Language — the query language used to search logs in Azure |
| **Syslog** | The standard Linux logging system |

## Prerequisites

- An active Azure subscription
- Azure CLI installed — download from https://aka.ms/installazurecli
- A terminal running **Bash** or **Azure Cloud Shell** (not Windows CMD)

Log in to Azure before starting:

```bash
az login
```

## Step 1 — Set Up Variables

Set these once at the start. All commands in this lab use them.

```bash
SUB_ID=$(az account show --query id -o tsv)
RG="rg-monitor-demo"
LOCATION="eastus2"
VM_NAME="vm-monitor-demo"
LAW_NAME="law-monitor-demo"
```

---

## Step 2 — Create a Resource Group and Virtual Machine

A resource group is a container that holds all your Azure resources together.

```bash
# Create resource group
az group create \
  --name $RG \
  --location $LOCATION
```

Now create the Linux VM:

```bash
az vm create \
  --resource-group $RG \
  --name $VM_NAME \
  --image Ubuntu2204 \
  --size Standard_B2s \
  --admin-username azureuser \
  --generate-ssh-keys \
  --public-ip-sku Standard
```

This command creates the VM along with a virtual network, public IP address, and network security group automatically.

Open port 22 so you can SSH into the VM later:

```bash
az vm open-port \
  --port 22 \
  --resource-group $RG \
  --name $VM_NAME
```

---

## Step 3 — Create a Log Analytics Workspace

This is the central place where all logs from your VM will be stored and queried.

```bash
az monitor log-analytics workspace create \
  --resource-group $RG \
  --workspace-name $LAW_NAME \
  --location $LOCATION
```

Save the workspace resource ID — you will need it in the next step:

```bash
LAW_ID=$(az monitor log-analytics workspace show \
  --resource-group $RG \
  --workspace-name $LAW_NAME \
  --query id -o tsv)

echo "LAW ID: $LAW_ID"
```

---

## Step 4 — Install Azure Monitor Agent on the VM

The Azure Monitor Agent (AMA) is an extension that runs on your VM and collects logs to send to Azure.

```bash
az vm extension set \
  --resource-group $RG \
  --vm-name $VM_NAME \
  --name AzureMonitorLinuxAgent \
  --publisher Microsoft.Azure.Monitor \
  --version 1.28 \
  --settings '{}'
```

Verify the agent installed successfully:

```bash
az vm extension show \
  --resource-group $RG \
  --vm-name $VM_NAME \
  --name AzureMonitorLinuxAgent \
  --query "provisioningState"
```

You should see `"Succeeded"`.

---

## Step 5 — Create a Data Collection Rule

A Data Collection Rule (DCR) tells the agent what logs to collect and where to send them. Here we collect all Syslog entries and send them to our Log Analytics Workspace.

```bash
az monitor data-collection rule create \
  --resource-group $RG \
  --name "dcr-syslog-demo" \
  --location $LOCATION \
  --data-flows '[{
    "streams": ["Microsoft-Syslog"],
    "destinations": ["law-dest"]
  }]' \
  --destinations '{
    "logAnalytics": [{
      "workspaceResourceId": "'"$LAW_ID"'",
      "name": "law-dest"
    }]
  }' \
  --data-sources '{
    "syslog": [{
      "name": "syslog-source",
      "streams": ["Microsoft-Syslog"],
      "facilityNames": ["*"],
      "logLevels": ["Debug","Info","Notice","Warning","Error","Critical","Alert","Emergency"]
    }]
  }'
```

Save the DCR resource ID:

```bash
DCR_ID=$(az monitor data-collection rule show \
  --resource-group $RG \
  --name "dcr-syslog-demo" \
  --query id -o tsv)

echo "DCR ID: $DCR_ID"
```

---

## Step 6 — Associate the DCR with Your VM

This step links the Data Collection Rule to your VM so the agent knows which rule to follow.

```bash
az rest \
  --method PUT \
  --url "https://management.azure.com/subscriptions/$SUB_ID/resourceGroups/$RG/providers/Microsoft.Compute/virtualMachines/$VM_NAME/providers/Microsoft.Insights/dataCollectionRuleAssociations/dcra-vm-demo?api-version=2022-06-01" \
  --body '{
    "properties": {
      "dataCollectionRuleId": "'"$DCR_ID"'"
    }
  }'
```

Verify the association:

```bash
az rest \
  --method GET \
  --url "https://management.azure.com/subscriptions/$SUB_ID/resourceGroups/$RG/providers/Microsoft.Compute/virtualMachines/$VM_NAME/providers/Microsoft.Insights/dataCollectionRuleAssociations?api-version=2022-06-01" \
  --query "value[].properties.provisioningState"
```

You should see `["Succeeded"]`.

---

## Step 7 — Assign Permissions to the VM

The VM needs permission to write data into the Log Analytics Workspace. Assign these two roles to the VM's managed identity.

```bash
# Get the VM's managed identity
VM_PRINCIPAL=$(az vm show \
  --resource-group $RG \
  --name $VM_NAME \
  --query identity.principalId -o tsv)

# Assign Monitoring Contributor
az role assignment create \
  --assignee $VM_PRINCIPAL \
  --role "Monitoring Contributor" \
  --scope $LAW_ID

# Assign Log Analytics Contributor
az role assignment create \
  --assignee $VM_PRINCIPAL \
  --role "Log Analytics Contributor" \
  --scope $LAW_ID
```

Wait 2–3 minutes after assigning roles before proceeding.

## Step 8 — SSH into the VM and Generate Dummy Logs

Get the VM's public IP address:

```bash
az vm show \
  --resource-group $RG \
  --name $VM_NAME \
  --show-details \
  --query publicIps -o tsv
```

Connect to the VM:

```bash
ssh azureuser@<YOUR_PUBLIC_IP>
```

Now generate dummy log entries using the `logger` command. This writes messages directly into the Linux Syslog system:

```bash
for i in $(seq 1 50); do
  logger -t "DummyApp" -p user.info    "INFO  - Application started, request #$i processed"
  logger -t "DummyApp" -p user.warning "WARN  - High memory usage detected, instance #$i"
  logger -t "DummyApp" -p user.err     "ERROR - Connection timeout on request #$i"
  sleep 1
done
```

Each iteration writes three log entries — Info, Warning, and Error — giving you 150 log entries in total.

## Step 9 — Query Logs in Log Analytics

Go to **Azure Portal → Log Analytics Workspace → Logs**.

Wait 3–5 minutes after running the script, then run these queries.

**Check agent connectivity — always run this first:**

```kql
Heartbeat
| where TimeGenerated > ago(30m)
| project TimeGenerated, Computer, Version
| order by TimeGenerated desc
```

If rows appear here, your agent is connected and sending data.

**View all DummyApp log entries:**

```kql
Syslog
| where TimeGenerated > ago(1h)
| where ProcessName == "DummyApp"
| project TimeGenerated, SeverityLevel, SyslogMessage
| order by TimeGenerated desc
```

**Count log entries grouped by severity:**

```kql
Syslog
| where TimeGenerated > ago(1h)
| where ProcessName == "DummyApp"
| summarize Count = count() by SeverityLevel
```

**Visualize as a pie chart:**

```kql
Syslog
| where TimeGenerated > ago(1h)
| where ProcessName == "DummyApp"
| summarize Count = count() by SeverityLevel
| render piechart
```

**View log trend over time:**

```kql
Syslog
| where TimeGenerated > ago(1h)
| where ProcessName == "DummyApp"
| summarize Count = count() by bin(TimeGenerated, 5m), SeverityLevel
| render timechart
```

## KQL Quick Reference

| Operator | What it does | Example |
|---|---|---|
| `where` | Filters rows | `where SeverityLevel == "err"` |
| `project` | Selects columns | `project TimeGenerated, SyslogMessage` |
| `summarize` | Aggregates data | `summarize count() by SeverityLevel` |
| `order by` | Sorts results | `order by TimeGenerated desc` |
| `render` | Visualizes output | `render piechart` |
| `ago()` | Relative time filter | `where TimeGenerated > ago(1h)` |
| `bin()` | Groups by time bucket | `bin(TimeGenerated, 5m)` |
